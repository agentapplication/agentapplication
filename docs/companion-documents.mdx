## From contracts to standards

The paper identifies several possible open contracts. A contract is ready for
standards work when two or more independent implementations need to exchange
the same information across a stable boundary.

The Agent Application capability model is not such a contract. It helps
developers compare frameworks and helps framework authors see the expected
surface area, but it does not prescribe project files, APIs, builds, or release
artifacts.

Likely candidates for future standards include:

1. **Agent Artifact contract.** This would cover identity, content and state,
   provenance, permissions, versions, rendering, and actions. See
   [Agent Artifact](/concepts/artifact) for the two-layer model.
2. **Workspace and lineage export.** This would carry portable state and its
   release and overlay history, using secret references instead of credentials.
3. **Agent identity and delegated authority.** This work comes later, after
   principal and cross-system authority models are mature enough to support a
   shared abstraction.

Each proposal should begin with implementation evidence and a concrete exchange
problem. The standard should cover that boundary without absorbing the native
project model of every framework on either side.
