Agent Applications is a public project about software in which agents use tools
and continue work across sessions. The [working paper](/paper) proposes a name,
vocabulary, and architecture for this kind of software.

The paper is an early attempt to describe an emerging category, not a finished
standard. Its claims need to be tested against real products, implementation
experience, prior art, and counterexamples.

## Project goals

The project has three goals:

1. Document the typical shape of an agent application as components such as
   MCP, skills, plugins, hooks, agent loops, and built-in tools mature.
2. Help developers of frameworks, tools, standards, and cloud services see what
   is still missing from the process of building, deploying, and managing these
   applications.
3. Give the community a place to refine the model as agent applications take on
   difficult work such as running businesses and conducting frontier research.

The project does not prescribe one framework or folder layout. Proposed
standards should address an interoperability problem between independent
implementations, rather than turn the design of one product into a requirement
for the category.

## Terms defined in the paper

- **[Agent Application](/paper#1-what-is-an-agent-application):** Software built
  around persistent, tool-using agents whose work can continue across sessions
  and leave durable results.
- **[Harness / Agent Application framework](/concepts/framework):** The
  development and runtime system used to build, test, deploy, and run an Agent
  Application.
- **[Agent Application Programming](/paper#8-7-agent-application-programming):**
  The practice of deciding how code, instructions, skills, tools, hooks, other
  agents, workflows, state, and policy work together for a particular use case.
- **[Agent Application Platform](/concepts/platform):** The service used to
  package, deploy, operate, update, and distribute Agent Applications.

## Contribute

The most useful feedback is specific. Tell us about a product that does not fit
the proposed category, an implementation that contradicts a claim, relevant
prior art, or a term that conflicts with established usage.

- Use [GitHub Discussions](https://github.com/agentapplication/agentapplication/discussions)
  for open-ended proposals, architecture questions, and boundary cases.
- Open an [issue](https://github.com/agentapplication/agentapplication/issues)
  for a concrete error, missing source, or broken page.
- Send a [pull request](https://github.com/agentapplication/agentapplication/pulls)
  for a focused correction, example, or documentation improvement.

[Read the review guide](/review) for the questions the draft most needs help
answering. The full contribution process is in
[CONTRIBUTING.md](https://github.com/agentapplication/agentapplication/blob/main/CONTRIBUTING.md).
Private feedback can be sent to the correspondence address below.
