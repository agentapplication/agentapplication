[Model Context Protocol
(MCP)](https://modelcontextprotocol.io/) standardizes how agents connect to
tools and data. The [Agent Skills
specification](https://agentskills.io/specification) defines an open format for
packaging instructions, scripts, and supporting material. Developers combine
them with plugins, hooks, agent loops, and built-in tools such as shell access
and code execution.

The Agent Applications project asks what the complete software product looks
like when developers put these parts together. The [working paper](/paper)
calls the result an Agent Application and proposes shared vocabulary and an
architecture for building, deploying, and operating one.

The paper is a working draft. We invite readers to test its claims against real
products, implementation experience, prior art, and counterexamples.

## Project goals

- Describe the typical shape of an agent application as its components mature.
- Identify the framework capabilities, developer tools, standards, and cloud
  services that could make these applications easier to build, deploy, and
  manage.
- Give practitioners a shared place to discuss the evolving nature of agent applications as agents gain widespread adoption.

## Core terms

- **[Agent Application](/paper#1-what-is-an-agent-application):** Software that
  uses one or more persistent, tool-using AI agents to produce work over time.
- **[Harness / Agent Application framework](/concepts/framework):** A system
  that runs the agent loop and supports project structure, testing,
  packaging, deployment, and the production runtime.
- **[Agent Application Programming](/paper#8-7-agent-application-programming):**
  The discipline of deciding which behavior belongs in code, instructions,
  skills, tools, hooks, agents, workflows, state, or policy, then composing
  those parts for a use case.
- **[Agent Application Platform](/concepts/platform):** A service that deploys
  and operates Agent Applications, manages fleets, updates, and costs, and
  supports distribution and monetization.
